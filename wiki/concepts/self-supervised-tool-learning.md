## 定义

来源：[Toolformer](../papers/202302-toolformer.md)

不依赖人工标注，让语言模型自己生成学用工具的训练数据：用少量示例提示模型在普通文本里插入候选 API 调用，执行这些调用，只保留"给了调用和结果后，后续 token 更容易预测"的那部分，再在插好调用的文本上微调模型本身（§1¶3）。它要解决的问题是：已有的工具使用要么依赖大量人工标注，要么只在特定任务里有效（§1¶2）；而且人觉得有用的调用不一定是模型觉得有用的（§1¶2）。

本库收录的来源是 2023-02 的 Toolformer。Toolformer 作者指出更早的 TALM 用了类似的自监督目标，但只在针对下游任务微调的设置下（§6¶2）；TALM 未收录，所以本页没有 `proposes` 来源，Toolformer 记为 `extends`。

## 设计空间

来源：[Toolformer](../papers/202302-toolformer.md)

下表按"用工具的能力从哪里来"排列，前两行和 TALM 一行取自 Toolformer 的相关工作，本库只收录了其中的 ReAct。

| 做法 | 监督信号 | 是否绑定任务 | 代表 | 代价与疑点 |
|---|---|---|---|---|
| 人工标注或人类反馈 | 人写的调用或偏好 | 视数据而定 | WebGPT、LaMDA 等（§6¶2） | 标注成本高（§1¶2） |
| 按任务写 few-shot 提示 | 无训练，靠示例 | 是，事先知道该用哪个工具（§6¶2） | PAL、[ReAct](../papers/202210-react.md) 等 | 用户不提前说明用什么工具时用不上（§4.2¶1） |
| 下游任务上的自监督微调 | 自监督目标 | 是 | TALM（§6¶2） | 只在针对下游任务微调的设置下验证过（§6¶2） |
| 通用语料上的自监督微调 | 后续 token 的加权损失降低至少 τf（§2¶7） | 否，用原预训练语料即可（§1¶4） | Toolformer | 每个输入只调用一次，不能链式或交互式使用（§7¶1）；部分工具样本效率很低（§7¶1） |

筛选标准的关键是比较对象：把"调用并给结果"的损失与"不调用"和"只调用不给结果"两者中较低的一个比（§2¶7），所以留下的调用必须靠返回结果本身起作用。阈值 τf 越高，留下的样本越少，问答工具在 τf 为 0.5、1.0、2.0 时分别留下 51,987、18,526、5,135 条（Tab. 2）。

## 共识与分歧

- 能力放在权重里还是放在提示和接口里。Toolformer 把何时调用、调什么训练进权重（[Toolformer](../papers/202302-toolformer.md) §2¶8）；[ReAct](../papers/202210-react.md) 用少量示例提示冻结的模型（[ReAct](../papers/202210-react.md) §2¶3）；SWE-agent 固定模型，只改 agent 能用的命令和反馈（[SWE-agent](../papers/202405-swe-agent.md) §2¶4）。三篇没有在同一任务上对照，但 ReAct 作者也发现小模型要靠微调才学会交替推理和行动（[ReAct](../papers/202210-react.md) §3.3¶8）。
- 学工具与保留通用能力不冲突，这一点在 Toolformer 的数据上成立：关掉 API 后困惑度与只在同一语料上微调的模型相同（[Toolformer](../papers/202302-toolformer.md) Tab. 8）。但它在多语言问答上不能稳定超过原始 GPT-J，作者归因于继续训练的语料造成分布偏移（[Toolformer](../papers/202302-toolformer.md) §4.2.4¶2）。
- 小模型和大模型的差距能靠工具补多少，因任务而异：有计算器时 6.7B 的模型在数学题上超过 175B 的 GPT-3（[Toolformer](../papers/202302-toolformer.md) Tab. 4），只有搜索时问答仍然落后（[Toolformer](../papers/202302-toolformer.md) Tab. 5）。作者把后者归因于搜索引擎太简单、模型不能改写查询或翻看结果（[Toolformer](../papers/202302-toolformer.md) §4.2.3¶2），这正是[推理与行动交替](interleaved-reasoning-acting.md)的多步交互能补上的部分。

## 开放问题

来源：[Toolformer](../papers/202302-toolformer.md)

- 怎样学会链式调用和交互式使用工具？各工具的调用独立采样，训练数据里没有链式调用的例子（§7¶1）。
- 调用多少次才算"模型自己决定"？评测时 `<API>` 只要排进前 10 就开始调用，普通贪心解码下的调用比例低得多（§5¶1）；贪心时调用时机有一定校准，放宽阈值后校准消失（§5¶1）。
- 样本效率：一百多万篇文档只换来几千条有用的计算器调用，作者设想像其他自举方法那样迭代应用（§7¶1）。
- 是否调用时没有考虑调用成本（§7¶1）。用工具的能力约在 775M 参数才出现（§4.4¶2），更大的模型和更多工具下这些结论是否不变？

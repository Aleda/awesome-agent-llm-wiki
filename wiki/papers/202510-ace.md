## 新认知

- **作者指出让 LLM 每一步整段重写累积的上下文有塌缩风险：AppWorld 上一份 18,282 token 的上下文下一步被重写成 122 token，准确率从 66.7 跌到 57.1，低于不做适应的 63.7（§2.2¶2）**；这是[记忆笔记](../concepts/memory-notes.md#设计空间)里"整份重写"一路的直接反例。
- **作者主张上下文应当是越积越全的 playbook，不该被压成简短的指令：模型能自己从长而详尽的上下文里挑出相关部分（§1¶4）**；这与[提示词压缩](../concepts/prompt-compression.md#共识与分歧)的方向相反，也和[长上下文位置偏差](../concepts/long-context-position-bias.md#共识与分歧)的观察有冲突。
- 解法是把上下文拆成带 ID 和"有用/有害"计数的条目，LLM 只写新增的增量条目，合并和去重交给确定性的非 LLM 逻辑（§3¶3、§3.1¶1）；AppWorld 上去掉增量更新，test-normal 平均从 70.3 降到 56.9（Tab. 18），这一设计是[记忆笔记](../concepts/memory-notes.md#设计空间)更新方式的一个新选项。
- 生成、反思、整理分给三个角色：Generator 做任务，Reflector 从成功和失败里提炼教训，Curator 把教训写成条目（§3¶1）；三个角色用同一个模型（§4.2¶6），所以收益来自上下文的构建方式，见[记忆笔记](../concepts/memory-notes.md)。
- 在 agent 任务上可以不靠标签，只用代码执行成败这类环境信号：AppWorld 上无标签的 ACE 平均比 ReAct 基线高 14.8 个点（§4.3¶2）；但金融任务上在线且没有标签时，FiNER 低于基础模型（Tab. 2），作者也承认缺少可靠反馈时上下文会被误导信号污染（§4.4¶2），这正是[记忆笔记](../concepts/memory-notes.md#开放问题)"错误经验写入后一直留存"的问题。
- 更长的上下文不一定更贵：评估阶段 ACE 的输入 token 是 GEPA 的两倍多（Tab. 14），但 GPT-5.1 的提示缓存命中了 91.8% 的输入，按计费口径输入成本降低 82.6%（§4.7¶4）；这与[频繁上下文压缩](../concepts/frequent-context-compaction.md#共识与分歧)"重开对话让缓存作废"相比，两者在缓存上的代价方向相反。
- ACE 在[模型自管理上下文](../concepts/model-managed-context.md#设计空间)那张表里占一行：模型决定写入什么，怎样合并由确定性逻辑决定（§3¶3），积累的策略跨 episode 复用（§4.1¶1），不管单个任务内的实时上下文。

## 核心问题

agent 和领域推理越来越依赖"改上下文、不改权重"的适应方式，即 context adaptation（§1¶1）。现有做法有两个毛病：提示优化器偏好简短通用的指令，丢掉领域细节，作者称为 brevity bias（§1¶3、§2.2¶1）；让 LLM 每一步整段重写已积累的上下文，内容会越写越短，最后突然塌缩，称为 context collapse（§2.2¶2）。本质上这是跨任务经验积累中的"写回"问题：每次更新都让 LLM 重写全部内容，等于每一步都对已有知识做一次有损压缩，错误会累积，也可能一次清空。

## 核心洞察

作者认为 LLM 与人不同，给它长而详尽的上下文更有效，它能自己挑出相关部分（§1¶4）。既然不必压缩，上下文就可以只增不改写：把它拆成独立的条目，每次只追加或局部更新几条，过去的知识就不会在重写中丢失（§3.1¶3）。

## 核心设计

1. **三个角色分工**：Generator 为新问题生成推理轨迹，并标出哪些条目有用、哪些误导；Reflector 评析轨迹、提炼教训，可以多轮迭代；Curator 把教训写成简短的增量条目（§3¶1、§3¶3、§3.1¶1）。把评估和提炼从整理中分出来，是作者在 Dynamic Cheatsheet 之上加的部分（§3¶2）。
2. **条目化的上下文**：每条 bullet 带唯一 ID 和"被标为有用/有害"的计数，内容是一条可复用的策略、领域概念或常见失败模式（§3.1¶1）。这样更新可以只动相关条目，Generator 也能只取相关条目（§3.1¶2）。
3. **增量更新、确定性合并**：Curator 只写新增部分，由轻量的非 LLM 逻辑合并进已有上下文；更新是局部的，所以多个增量可以并行合并（§3¶3）。这一步避开了整段重写的成本和塌缩（§3.1¶3）。
4. **grow-and-refine**：新 ID 的条目追加，已有条目原地更新计数，再按语义 embedding 去重；去重可以在每次增量后做，也可以等超出 context window 时再做（§3.2¶1）。
5. **离线与在线两种用法**：离线时在训练集上多轮反复优化系统提示（§3¶3）；在线时对测试集逐个样本先预测、再根据该样本更新上下文（§4.1¶4）。

## 局限与疑点

### 作者承认的

- 依赖足够强的 Reflector：提炼不出有用教训时，上下文会变得嘈杂甚至有害（§5¶2）。
- 缺少标签或可靠执行信号时，ACE 和 DC 都可能变差，上下文会被误导信号污染（§4.4¶2）。
- 不是所有任务都需要详尽的上下文，HotPotQA 这类任务更适合简短的高层指令（§5¶2）。
- 底座模型越弱收益越小：Llama-3.3-70B 上 FiNER 只从 62.5 提到 64.9（Tab. 9）。

### 本库判断的

- 头条数字是几组差值的平均。正文说离线时比 ICL、GEPA 高 12.3 和 11.9 个点（§4.3¶1），这与 Tab. 1 里有标签（59.4）和无标签（57.2）两种 ACE 的平均值减去基线一致；"agent 任务平均高 10.6%"再对 ICL、GEPA、DC 三组差值（12.3、11.9、7.6）取平均（Tab. 1）。差值的单位是百分点，按 TGC/SGC 的平均算，读者容易误读为相对提升。
- Tab. 1 里在线 ACE 那一行（平均 59.5）与消融表里"在线 + 离线预热"一行的数字完全相同，不预热的在线 ACE 是 56.1（Tab. 3）。所以在线设置下与 DC（51.9）比的是先经过离线预热的 ACE，DC 没有预热。
- 与 IBM CUGA 的比较前后不一：引言说 ACE 超过排行榜第一（§1¶6），结果一节写平均 59.4% 对 60.3% 是"持平"，只在 test-challenge 的在线设置上更高，脚注又说 CUGA 不是方法基线、不做直接比较（§4.3¶3）。
- 金融任务上无标签的在线 ACE 在 FiNER 上低于基础模型（67.3 对 70.7，Tab. 2），无标签的离线 ACE 只高 0.4 个点（71.1，Tab. 2）。agent 任务有代码执行结果可用，其他领域往往没有，这限制了"不需要标签"这一卖点。
- "长而详尽的上下文更有效"是作者的主张（§1¶4），论文自己的数据没有直接支持：FiNER 上修剪上限从 100K 降到 10K，准确率不降反升（Tab. 21）。Lost in the Middle 报告的位置偏差（[Lost in the Middle](./202307-lost-in-the-middle.md) §1¶5）在 playbook 变长后是否出现，论文没有测。
- context collapse 只用 Dynamic Cheatsheet 的一次运行举例（§2.2¶2、Fig. 2），没有报告塌缩发生的频率；作者认为这是 LLM 整段重写的普遍风险，证据只有这一个案例。
- 评估阶段输入 token 是 GEPA 的 2.17 倍（Tab. 14），缓存省钱的结论来自一个 API 提供商的默认缓存（§4.7¶4），自部署时要看推理框架。
- 合并和去重是确定性的，但条目只增不删，删除只靠去重和超长时修剪（§3.2¶1）；被推翻的旧策略怎样清除，论文只在附录提到计数和修剪可以过滤有害条目，没有专门评估。

## 与其他工作的关系

- 与 [Dynamic Cheatsheet](../glossary.md#dynamic-cheatsheet)、[GEPA](../glossary.md#gepa)：两者是 ACE 的主要基线，本库没有收录原文。ACE 的三角色借鉴了 Dynamic Cheatsheet 的 agent 化设计（§3¶1），区别在更新方式：DC 每一步重写整份 cheatsheet，ACE 只写增量（论文附录 C.2）。GEPA 每次生成完整的候选提示词，偏好简短（§1¶3）。
- 与 [A-MEM](./202502-a-mem.md)：ACE 说它的 bullet 类似 A-MEM 和 Dynamic Cheatsheet 里的记忆条目，并在其上加了计数元数据（§3.1¶1）。两者都在写入时整合，区别在存的内容和合并方式：A-MEM 存交互内容，由 LLM 改写近邻笔记的描述和标签（[A-MEM](./202502-a-mem.md) §3.3¶1），见[写入时记忆整合](../concepts/memory-consolidation.md)；ACE 存策略和教训，合并不调用 LLM（§3¶3）。
- 与 [Context Language Models](./202609-context-language-models.md)：CLM 让模型任意改写单个任务里的实时上下文（[CLM](./202609-context-language-models.md) §4.1¶2），ACE 只允许跨任务的 playbook 逐条增长。ACE 报告的 context collapse 来自整段重写累积上下文（§2.2¶2），对 CLM 这类任意改写是一个提醒，但 CLM 的编辑多是局部的，两篇没有直接对照，见[模型自管理上下文](../concepts/model-managed-context.md#共识与分歧)。
- 与 [LLMLingua](./202310-llmlingua.md) 和 [You don't need long context](./202611-you-dont-need-long-context.md)：LLMLingua 和 NVIDIA 论文都在压缩输入，ACE 反对把积累的知识压缩掉（§1¶4）。压缩的对象不同：这两篇压缩单次调用或单个任务的输入，ACE 保留的是跨任务的策略。
- 与 Reflexion：ACE 把 Reflexion 列为用自然语言反馈改上下文的代表，后者通过反思失败改进 agent 的规划（§2.1¶1）。Reflexion 本库待录入。

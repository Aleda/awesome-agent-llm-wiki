## 新认知

- **ReAct 把 agent 的动作空间扩成"环境动作 + 语言"：语言动作叫 thought，它不影响环境，只把推理结果写回上下文，用来分解目标、提取观察里的要点、跟踪进度和处理异常（§2¶2）；推理为行动制定计划，行动为推理取回外部信息（§1¶3）**，本库把它记为[推理与行动交替](../concepts/interleaved-reasoning-acting.md)的最早来源。
- **收益集中在长程决策任务上：ALFWorld 上 ReAct 最好的一组提示成功率 71%，只行动的 Act 最好一组 45%，用每类 10^5 条专家轨迹训练的 BUTLER 37%（Tab. 3、§4¶2）；WebShop 成功率 40.0，Act 30.1（Tab. 4）**，见[推理与行动交替](../concepts/interleaved-reasoning-acting.md#设计空间)。
- 在知识问答上交替不一定占优：HotpotQA 上单用 ReAct 是 27.4，低于 CoT 的 29.4，也低于既不推理也不行动的 Standard 28.7（Tab. 1）；作者认为交替的结构约束降低了组织推理步骤的灵活性（§3.3¶4），见[推理与行动交替](../concepts/interleaved-reasoning-acting.md#共识与分歧)。
- 推理和检索的失败方向相反：CoT 的失败里 56% 是幻觉，ReAct 是 0%；ReAct 的失败里 47% 是推理错误，23% 是搜索没返回有用信息（Tab. 2），作者因此让两者互为退路，HotpotQA 提到 35.1、FEVER 提到 64.6（Tab. 1、§3.2¶3），见[推理与行动交替](../concepts/interleaved-reasoning-acting.md#设计空间)。
- 推理写什么比有没有推理更要紧：thought 只复述环境反馈的 ReAct-IM 在 ALFWorld 上成功率 53%，ReAct 71%（§4¶7）；作者把 Inner Monologue 看作最接近的前作，区别在它的"独白"只限于环境状态和还要完成什么（§4¶6），见[推理与行动交替](../concepts/interleaved-reasoning-acting.md#设计空间)。
- 小模型靠提示学不会交替，靠微调可以：PaLM-8B/62B 上提示式 ReAct 是四种方法里最差的，用 3,000 条 ReAct 轨迹微调后变成最好（§3.3¶8）；作者认为用更多人写数据微调才是发挥 ReAct 的方式（§3.3¶8），见[推理与行动交替](../concepts/interleaved-reasoning-acting.md#开放问题)。
- thought 给了人一个介入点：人可以随时编辑 thought 来纠正 agent 的行为（§2¶4），ALFWorld 的例子里删掉一句幻觉、补一点提示，agent 就改变了做法（Fig. 5），见[推理与行动交替](../concepts/interleaved-reasoning-acting.md)。

## 核心问题

只推理的 chain-of-thought 用模型的内部表示生成推理，不接触外部世界，会出现事实幻觉和推理过程中的误差传播（§1¶2）。用语言模型在交互环境里规划和行动的工作，只用语言先验预测动作，不对高层目标做抽象推理，也不维护支撑行动的工作记忆（§1¶2）。本质上这是一个序列决策问题：agent 的策略要从上下文映射到下一个动作，这个映射很隐含、需要大量计算时，直接预测动作就会失败（§2¶1）。

## 核心洞察

语言本身可以当作一种动作：把动作空间扩成环境动作与语言空间的并集，语言动作不产生观察，只把对当前上下文的推理写回上下文（§2¶2）。语言空间无限大、难以学习，所以要靠大模型的语言先验，用少量示例提示就能让模型在这个空间里行动（§2¶3）。

## 核心设计

1. **扩展动作空间**：每一步可以输出环境动作或 thought，thought 更新上下文供后续推理和行动使用（§2¶2）。
2. **少量人写轨迹做提示**：底座是冻结的 PaLM-540B（§2¶3）；HotpotQA 和 FEVER 各从训练集随机取 6 条和 3 条，人工写成 ReAct 格式（§3.2¶1），ALFWorld 每类任务标注 3 条（§4¶2）。基线 Standard、CoT、Act 都由同一批轨迹删去相应部分得到（§3.2¶2）。
3. **thought 的密度按任务定**：知识推理任务每一步都是 thought、action、observation；动作很多的决策任务让模型自己决定何时插入 thought（§2¶3）。
4. **刻意做弱的 Wikipedia API**：只有 search、lookup、finish 三个动作，search 返回词条前 5 句，lookup 返回下一句含关键词的句子；作者承认它远弱于现有检索器，目的是模拟人查 Wikipedia 的方式，迫使模型通过推理来检索（§3.1¶2）。
5. **与 CoT-SC 互为退路**：ReAct 在给定步数内没给出答案就退回 CoT-SC；CoT-SC 的多数答案不到一半样本时退回 ReAct（§3.2¶3）。
6. **自举微调**：用 ReAct 生成的 3,000 条答对的轨迹微调 PaLM-8B/62B，做法类似 STaR（§3.2¶4）。

主实验用 PaLM-540B 提示，[HotpotQA](../glossary.md#hotpotqa) 指标为 EM，[FEVER](../glossary.md#fever) 为准确率。

## 局限与疑点

### 作者承认的

- 交替的结构约束让推理不够灵活；ReAct 常重复生成之前的 thought 和 action，跳不出循环（§3.3¶4）。
- 搜索没返回有用信息的情形占错误的 23%，一旦出现，模型很难恢复和改写思路（§3.3¶5）。
- 动作空间大的复杂任务需要更多示例，很容易超出上下文学习的输入长度（§6¶1）。
- 所有提示方法都离领域内监督学习的 SoTA 很远（§3.3¶8）；WebShop 上离人类专家也很远，专家会做多得多的商品探索和查询改写（§4¶5）。
- 让 LLM 接上能作用于外部环境的动作空间有风险，如查到不当或隐私信息、做出有害动作；实验只在 Wikipedia 和 WebShop 上进行，动作空间里没有危险动作（论文 Ethics Statement 一节）。

### 本库判断的

- Tab. 1 里最好的两行都是 ReAct 与 CoT-SC 的组合；单用 ReAct 在 HotpotQA 上没有赢过 Standard 和 CoT（Tab. 1）。"推理加行动更好"在这篇论文里主要由 FEVER 和两个决策任务支撑。
- ALFWorld 的头条数字 71% 是 6 组提示里最好的一组，平均是 57%（Tab. 3），Act 只报告了最好一组 45%。按平均算 ReAct 仍然领先，但幅度比头条数字小。
- Wikipedia API 被有意做弱（§3.1¶2），ReAct 和 Act 的检索能力都被压低。知识任务上的结论能否推到有强检索器的场景，论文没有测。
- 两张表的 PaLM-540B HotpotQA 数字不同：Tab. 1 是 27.4，Tab. 5 是 29.4，后者是 500 道验证题的子集（Tab. 5）。跨表比较要注意口径。
- 主实验用的 PaLM-540B 不公开，作者在 Reproducibility Statement 一节说明了这一点，复现只能依赖附录里的 GPT-3 结果。
- 正文有两处图表编号引用有误：讲 CoT-SC 采样数的那句写的是 Figure 1（§3.3¶7），对应的图是 Fig. 2；ALFWorld 和 WebShop 的结果都写成 Table 4（§4¶4），ALFWorld 实际在 Tab. 3。
- venue 记为 ICLR 2023：arXiv comment 写明 v3 是 ICLR camera ready 版本，PDF 页眉写的是 ICLR 2023。Shunyu Yao 和 Karthik Narasimhan 署 Princeton（Shunyu Yao 的工作在 Google 实习期间完成），其余作者署 Google Research 的 Brain team。

## 与其他工作的关系

- 与 [Toolformer](./202302-toolformer.md)：Toolformer 在相关工作里把 ReAct 归入"针对特定任务、用 few-shot 提示教模型用工具"的一类（[Toolformer](./202302-toolformer.md) §6¶2）。两者都让模型自己决定何时调用外部工具，区别在能力放在哪里：ReAct 用少量示例提示冻结的模型、可以多步交互（§2¶3）；Toolformer 把调用时机训练进权重，每个输入最多调用一次（[Toolformer](./202302-toolformer.md) §4.2¶2）。见[自监督工具使用学习](../concepts/self-supervised-tool-learning.md#设计空间)。
- 与 [SWE-agent](./202405-swe-agent.md)：SWE-agent 每一步生成一条 thought 和一条命令，明确沿用 ReAct（[SWE-agent](./202405-swe-agent.md) §3¶1），两篇有共同作者 Shunyu Yao 和 Karthik Narasimhan。SWE-agent 把注意力从循环本身移到循环里 agent 能用的命令和看到的反馈上，见[面向 agent 的计算机接口](../concepts/agent-computer-interface.md)。
- 与 [ACE](./202510-ace.md) 和 [You don't need long context](./202611-you-dont-need-long-context.md)：两篇都以 ReAct 式循环为基础。ACE 报告的 AppWorld 提升是相对 ReAct 基线算的（[ACE](./202510-ace.md) §4.3¶2）；NVIDIA 论文的 harness 是每轮发一个 Bash 动作的极简 ReAct 循环（[NVIDIA 论文](./202611-you-dont-need-long-context.md) §2.4）。
- 与 STaR：ReAct 的微调借鉴了 STaR 用模型自己答对的轨迹做训练的自举方式（§3.2¶4），STaR 本库待录入。
- 与 [Reflexion](./202303-reflexion.md)：Reflexion 在 ALFWorld 和 HotPotQA 上用 ReAct 作 Actor（[Reflexion](./202303-reflexion.md) §4.1¶1、[Reflexion](./202303-reflexion.md) §4.2¶1），在多次尝试之间加一段文字反思；ALFWorld 上 ReAct 自身重试在第 6–7 次之间停止提升，加反思后解决 134 个环境中的 130 个（[Reflexion](./202303-reflexion.md) §4.1¶3），见[语言反馈强化](../concepts/verbal-reinforcement.md)。

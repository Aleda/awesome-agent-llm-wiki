## 新认知

- **作者把 context window 当作受限的主存，借操作系统的虚拟内存分页，让模型自己决定把什么放进上下文、把什么换出到外部存储，在固定窗口的模型上制造"无限上下文"的假象（§1¶3、§1¶5）**；本库把它记为[模型自管理上下文](../concepts/model-managed-context.md)的最早来源。
- 控制权分两层：何时必须腾空间由系统按 token 阈值决定，到 70% 发记忆压力警告，到 100% 驱逐一部分消息并更新递归摘要（§2.2¶2）；存什么、取什么由模型通过函数调用自己决定（§2.3¶1），这种分工在[模型自管理上下文](../concepts/model-managed-context.md#设计空间)里介于 harness 规则和 CLM 的任意编辑之间。
- **模型能改写的上下文只有一块固定大小的 working context，系统指令只读，消息队列由队列管理器维护（§2.1¶1）**；可编辑的范围由人划定，这是 MemGPT 与后来 CLM 改写整个实时上下文的主要差别，见[模型自管理上下文](../concepts/model-managed-context.md#设计空间)。
- 让自编辑起作用的前提是模型知道上下文快满了，所以系统要持续把 token 限制告诉它（§2.3¶2）；CLM 论文后来也报告模型估不准自己用了多少上下文（[CLM](./202609-context-language-models.md) Fig. 30），见[模型自管理上下文](../concepts/model-managed-context.md#开放问题)。
- 在多会话对话上，GPT-4 加 MemGPT 回答关于旧会话的问题准确率 92.5%，只读递归摘要的 GPT-4 是 32.1%（Tab. 2）；本库判断：基线拿到的是有损摘要，MemGPT 能分页检索完整历史（§3.1.1¶3），这组数字比较的是"按需取回原文"和"只留摘要"，见[模型自管理上下文](../concepts/model-managed-context.md#共识与分歧)。
- 收益依赖底座模型的函数调用能力：换成 GPT-3.5 后文档问答明显变差（§3.2.1¶6），模型也常在翻完检索结果前就停下（§3.2.1¶5），和后来 CLM、NVIDIA 论文"能力依赖模型"的观察方向一致，见[模型自管理上下文](../concepts/model-managed-context.md#共识与分歧)。
- 作者认为单纯扩窗口不够：算力随长度二次增长，长上下文模型也用不好多出来的上下文（§1¶2），所以选择在固定窗口上做内存层级（§4¶1）；NVIDIA 论文后来也主张不靠扩窗口（[NVIDIA 论文](./202611-you-dont-need-long-context.md) §3¶4），见[频繁上下文压缩](../concepts/frequent-context-compaction.md)。

## 核心问题

固定长度的 context window 让 LLM 撑不过几十轮对话，也读不完一份长文档（§1¶1）。直接扩窗口，自注意力的算力和显存随长度二次增长，而且有研究显示长上下文模型用不好多出来的上下文（§1¶2），作者引的是 [Lost in the Middle](./202307-lost-in-the-middle.md)。本质上这是在有限的快速存储上提供更大的可用存储，也就是操作系统虚拟内存要解决的那类问题（§1¶5）：要回答的是谁、按什么策略决定哪些内容此刻在窗口里。

## 核心洞察

LLM 的函数调用能力可以充当操作系统的换页机制：模型能读写外部数据源、修改自己的上下文、决定何时回复用户（§1¶3），于是"把什么放进窗口"可以交给模型自己管理，窗口就成了一级可以换入换出的主存（§1¶4）。

## 核心设计

1. **两级记忆**：main context 是 prompt token，模型推理时可见；external context 是窗口之外的一切，必须显式搬进 main context 才能被看到（§2¶1）。外部又分两种：recall storage 存全部消息历史，archival storage 存任意长度的文本（§2.2¶1、§2.2¶2）。
2. **main context 分三段**：只读的系统指令（说明记忆层级和函数用法）、固定大小且只能通过函数调用改写的 working context（对话中存用户和人设的关键事实）、滚动的 FIFO 消息队列，队首放被驱逐消息的递归摘要（§2.1¶1）。
3. **队列管理器控制溢出**：prompt 超过警告阈值（如窗口的 70%）时插入记忆压力警告，给模型机会把重要内容存进 working context 或 archival storage；超过刷新阈值（如 100%）时驱逐一部分消息、更新递归摘要，被驱逐的消息仍留在 recall storage 里可以检索（§2.2¶2）。
4. **自主读写**：模型根据当前上下文自己决定何时在各层之间搬运数据、何时改写 main context（§2.3¶1）；检索结果分页返回，避免一次调用撑爆窗口（§2.3¶2）。
5. **事件驱动与函数链**：用户消息、系统警告、定时事件都会触发推理（§2.4¶1）；函数带一个标志位时，执行完立即把控制权交回模型，可以连续调用多次再回复用户，用来翻页检索或多跳查找（§2.4¶2、Fig. 3）。

## 局限与疑点

### 作者承认的

- MemGPT 的效果依赖底座模型的函数调用能力，用 GPT-3.5 时文档问答明显变差，用 GPT-4 最好（§3.2.1¶6）。
- 文档问答里 MemGPT 理论上能翻遍全部检索结果，实际常在翻完之前停下（§3.2.1¶5）。
- 嵌套 KV 上 MemGPT 配 GPT-4 Turbo 反而不如配 GPT-4（Fig. 7）。
- 控制流和记忆管理策略还有改进空间，作者把它列为未来工作（§5¶1）。

### 本库判断的

- DMR 的对话很短：每段 MSC 对话五次会话、每次约十几条消息（§3.1¶3），放得进 GPT-4 Turbo 的 128K 窗口（§3¶2）。基线拿到的却是有损摘要（§3.1.1¶3），所以 Tab. 2 没有回答"MemGPT 比把完整历史放进上下文好不好"。
- 嵌套 KV 的 140 对 UUID 约 8K token，正好是 GPT-4 基线的窗口（§3.2.2¶1），测的是多跳查找时逐步检索的价值，输入本身并不超长。
- 两个对话任务都用 LLM judge 评分，DMR 的评分提示要求"宽松打分"，只要提到与标准答案相同的话题就算对（§6.1.2¶1），准确率可能偏高；基线和 MemGPT 用的是同一个评分器。
- 文档问答只抽了 50 题（§3.2.1¶3），结果只以曲线给出（Fig. 5），没有报告方差。
- 自编辑意味着模型可以把错误或被注入的内容写进 working context 并长期保留；论文没有讨论记忆完整性。CLM 作者后来把可编辑上下文列为新的攻击面（[CLM](./202609-context-language-models.md) §6¶1）。
- arXiv 的 comment 字段只写了代码和数据地址，原文没有写投稿会议，所以 venue 记为 arXiv。全部作者署名 UC Berkeley。

## 与其他工作的关系

- 与 [Generative Agents](./202304-generative-agents.md)：MemGPT 在相关工作里把它概括为给 LLM 加记忆、用 LLM 做规划（§4¶3）。两者都把经历存在上下文之外，区别在取回由谁决定：Generative Agents 每一步按近因、重要性、相关性的固定打分取回（[Generative Agents](./202304-generative-agents.md) §4.1¶7），MemGPT 让模型自己发起检索（§2.3¶1）。
- 与 [Context Language Models](./202609-context-language-models.md)：CLM 在附录的相关工作里把 MemGPT 描述为用内存层级把上下文管理和外部记忆连起来、只允许模型编辑上下文中一块指定的固定大小区域；CLM 把编辑范围放开到整个实时上下文（[CLM](./202609-context-language-models.md) §4.1¶2）。本库把两者放在[模型自管理上下文](../concepts/model-managed-context.md#设计空间)的同一张表里。
- 与 [You don't need long context](./202611-you-dont-need-long-context.md)：两篇都认为不该靠一味扩窗口。MemGPT 的递归摘要和驱逐由系统按阈值触发（§2.2¶2），机制上接近 NVIDIA 的阈值压缩（[NVIDIA 论文](./202611-you-dont-need-long-context.md) §2.4.1）；MemGPT 另外保留了全部原始消息供模型检索，NVIDIA 把这一做法列为补救方案，没有实验（[NVIDIA 论文](./202611-you-dont-need-long-context.md) §3.1¶4）。
- 与 [A-MEM](./202502-a-mem.md)、[Mem0](./202504-mem0.md)：两篇都把 MemGPT 当基线，在 [LoCoMo](../glossary.md#locomo) 上报告超过它（[A-MEM](./202502-a-mem.md) Tab. 1）。MemGPT 由模型自己决定何时读写记忆，A-MEM 和 Mem0 在每次写入时都跑一遍固定管线，由 LLM 决定怎样改写已有记忆，见[写入时记忆整合](../concepts/memory-consolidation.md#设计空间)。

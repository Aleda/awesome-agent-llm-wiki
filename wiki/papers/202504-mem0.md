## 新认知

- **作者认为更长的 context window 只能推迟、不能解决长期记忆问题：对话迟早超出窗口，而且话题跳来跳去，全文里大部分内容和当前问题无关（§1¶3）**，所以只保留抽取出的要点，见[写入时记忆整合](../concepts/memory-consolidation.md)。
- **写入的核心是一个由 LLM 做的四选一：每条新抽取的事实和 10 条最相似的旧记忆一起交给模型，由它选 ADD、UPDATE、DELETE 或 NOOP（§2.1¶3、§2.1¶4）**；被新信息否定的旧记忆直接删掉，这是[写入时记忆整合](../concepts/memory-consolidation.md#设计空间)里改动最激进的一种。
- 图变体 Mem0^g 在同一问题上做了相反的选择：冲突的旧关系标为失效、不物理删除，以便做时间推理（§2.2¶5）；作者报告它在时间类问题上最好（Tab. 1），见[写入时记忆整合](../concepts/memory-consolidation.md#共识与分歧)。
- 图结构只在部分问题上有用：Mem0^g 在单跳和多跳问题上都不如纯文本的 Mem0，作者自己也说预期的关系优势没有出现（§4.2¶1）；改记忆的方式和记忆的存储结构是两个独立的选择，见[写入时记忆整合](../concepts/memory-consolidation.md#设计空间)。
- **把整段对话（约 26K token）放进上下文仍然是 J 分最高的做法，72.90 对 Mem0 的 66.88（Tab. 2）；Mem0 换来的是 p95 总延迟从 17.117 秒降到 1.440 秒，每次查询的上下文从约 26K token 降到约 1.8K（Tab. 2）**。本库判断：这是一个用少量准确率换延迟和成本的取舍，见[写入时记忆整合](../concepts/memory-consolidation.md#共识与分歧)。
- 本库判断：结果全部是作者自测，指标 J 由 LLM 评判，评判提示改编自 MemGPT 的"宽松打分"提示（论文附录 A）；部分基线不可比，例如 OpenAI 的记忆是作者在 ChatGPT 里生成后整体作为上下文（§3.3¶6），A-MEM 的分数由作者重跑得到（Tab. 1），所以[写入时记忆整合](../concepts/memory-consolidation.md#共识与分歧)里各系统的排名只能当作者自述看。

## 核心问题

固定的 context window 让 LLM 在跨多次会话的对话里无法保持一致：信息一出窗口就被"重置"，用户说过的偏好会被遗忘或违背（§1¶1）。扩窗口只是推迟问题，而且全文里大量内容与当前问题无关，注意力也会随距离衰减（§1¶3）。本质上这是一个在线的知识库维护问题：对话不断产生新事实，其中一些补充、一些推翻旧事实，系统要在每轮之后把知识库保持一致、紧凑、可检索。

## 核心洞察

把每轮对话增量地加工成少量事实，并在写入时就和已有记忆对齐，比在查询时检索原文片段更准，也比整段读入更省（§4.3¶1、§4.3¶2）。对齐的判断不需要单独训练分类器，直接交给 LLM 用函数调用完成（§2.1¶3）。

## 核心设计

1. **抽取**：每来一对消息，把数据库里的对话摘要、最近 m 条消息和这对新消息拼成 prompt，让 LLM 从新消息里抽出候选事实（§2.1¶2）。摘要由一个异步模块定期刷新，不拖慢主流程（§2.1¶2）。
2. **更新**：每条候选事实先按向量相似度取 s 条旧记忆，再通过函数调用让 LLM 选择 ADD（没有等价记忆时新增）、UPDATE（用补充信息增强旧记忆）、DELETE（删掉被新信息否定的旧记忆）或 NOOP（不改）（§2.1¶3）。实验取 m = 10、s = 10，所有 LLM 操作用 GPT-4o-mini（§2.1¶4）。
3. **图变体 Mem0^g**：记忆存成有向带标签图，节点是实体，边是关系三元组（§2¶1）。先抽实体，再生成关系；新三元组按实体嵌入相似度并入已有节点，冲突的旧关系由 LLM 判定后标为失效，不删除（§2.2¶5）。检索结合以实体为中心的子图展开和三元组的语义匹配（§2.2¶6），图存储用 Neo4j（§2.2¶7）。

## 效果

所有数字是作者在 [LOCOMO](../glossary.md#locomo) 上自测的结果（10 段对话，平均约 600 轮、26000 token，§3.1¶1），去掉了没有标准答案的对抗类问题（§3.1¶1）。J 为 LLM-as-a-Judge 分数，10 次运行取均值（§3.2¶2）。

| 设置 | 基线 | 结果 | 锚点 |
|---|---|---|---|
| 整体 J | 全文放进上下文 72.90；Zep 65.99；最好的 RAG（k = 2，256 token 块）60.97；LangMem 58.10；OpenAI 52.90；A-MEM 48.38 | Mem0 66.88，Mem0^g 68.44 | （Tab. 2） |
| 分类 J：单跳 / 多跳 / 开放域 / 时间 | 各类最强基线：OpenAI 63.79 / LangMem 47.92 / Zep 76.60 / A-MEM（作者重跑）49.91 | Mem0 67.13 / 51.15 / 72.93 / 55.51；Mem0^g 65.71 / 47.19 / 75.71 / 58.13 | （Tab. 1） |

## 局限与疑点

### 作者承认的

- 全文放进上下文的 J 分仍然最高（§4.3¶2），Mem0 是在准确率和延迟、token 之间取舍。
- 开放域问题上 Zep 最好，Mem0 和 Mem0^g 略低（§4.1¶4）。
- Mem0^g 的关系结构在多跳问题上没有带来收益，作者推测是图结构的开销或冗余（§4.2¶1）；图操作的延迟还需要优化（§5¶2）。
- LOCOMO 原有的对抗类问题因为没有标准答案被去掉（§3.1¶1）。
- OpenAI 基线无法通过 API 选择性检索记忆，作者把它生成的全部记忆都当作上下文，有意给了它"特权"（§3.3¶6）；它的延迟数字不包括人工预先抽取记忆的时间（§4.4¶1）。

### 本库判断的

- 自测基准：作者是 Mem0 公司（署名邮箱 research@mem0.ai），对比对象包括同类产品 [Zep](../glossary.md#zep) 和 LangMem。Zep 的延迟和可用性问题（几小时后检索才变好，§4.5¶1）来自作者自己的使用观察，没有第三方复核。
- 评分器宽松：J 的提示改编自 MemGPT 的评分提示（论文附录 A），要求"只要涉及与标准答案相同的话题就算对"。这会抬高所有方法的分数，对冗长回答更有利，不同方法之间的差距含义不明。
- 基线来源混杂：LoCoMo、ReadAgent、MemoryBank、MemGPT 和 A-MEM 的 F1/B1 直接取自已发表结果，选的是用 gpt-4o-mini 评测的那组（§3.3¶2），这些基线没有 J 分；A-MEM 的 J 分是作者重跑得到，重跑的 F1 比原文低，如单跳 20.76 对 27.02（Tab. 1）。
- 类别映射与 A-MEM 原文不一致：本文 Tab. 1 里 A-MEM 的单跳、多跳、开放域三列分别对应 A-MEM 原文的 Multi Hop、Open Domain、Single Hop 三列（[A-MEM](./202502-a-mem.md) Tab. 1）。两篇对 LOCOMO 类别的命名至少有一篇不对，跨论文比较分类结果要谨慎。
- 摘要说 p95 延迟降低 91%（§5¶1），引言写成"响应时间低 91%"（§1¶4）；按 Tab. 2 计算，Mem0 的 p95 总延迟比全文低约 92%，p50 低约 93%，两个说法都与表一致，但口径不同。
- 摘要里"时间类提升 11%"（§5¶1）与 Tab. 1 对得上的是 Mem0 对最强基线（55.51 对 49.91）；同一类别 J 分最高的是 Mem0^g（58.13），按它算约 16%。
- 只有一个 benchmark、一个底座模型（GPT-4o-mini，§2.1¶4），10 段对话（§3.1¶1）。DELETE 会物理删除被判定为矛盾的记忆（§2.1¶3），判错时信息无法找回，论文没有评估误删率。
- arXiv comment 字段为空，原文没有写投稿会议，venue 记为 arXiv。

## 与其他工作的关系

- 与 [A-MEM](./202502-a-mem.md)：A-MEM 把 Mem0 当作依赖预定义 schema 的例子（[A-MEM](./202502-a-mem.md) §1¶2），本文把 A-MEM 当作基线（Tab. 1）。两者都是"新信息进来时取相似旧记忆，交给 LLM 决定怎样改"；A-MEM 改的是旧笔记的描述、标签和链接（[A-MEM](./202502-a-mem.md) §3.3¶1），本文改的是事实本身，可以合并或删除。本库把两者合在[写入时记忆整合](../concepts/memory-consolidation.md)一页里比较。
- 与 [MemGPT](./202310-memgpt.md)：MemGPT 由模型在对话中自己决定何时把信息写进记忆（[MemGPT](./202310-memgpt.md) §2.3¶1）；本文每轮固定跑一次抽取和更新，模型只决定怎样改。本文的 J 评分提示也借自 MemGPT（论文附录 A）。
- 与 [Generative Agents](./202304-generative-agents.md)：Generative Agents 的记忆流只追加新条目，反思也作为新记忆写入（[Generative Agents](./202304-generative-agents.md) §4.2¶3）；本文在写入时就消解矛盾。Mem0^g 的"标为失效不删除"（§2.2¶5）介于两者之间。
- 与 [You don't need long context](./202611-you-dont-need-long-context.md)：两篇都认为全文放进上下文不划算。NVIDIA 论文看的是长程任务里不断压缩工作上下文，本文看的是跨会话对话里只留事实；两者都以全文为准确率上限，本文的全文基线仍然最高（Tab. 2）。

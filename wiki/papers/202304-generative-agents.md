## 新认知

- **作者认为 agent 的长期记忆不能靠把全部经历压成摘要：对"最近热衷什么"这类问题，摘要给出的回答空泛，按问题从记忆流里检索才答得具体（§4.1¶1）**，这是[记忆流与反思](../concepts/memory-stream-reflection.md)的出发点。
- 取回什么由一个固定的打分函数决定：近因、重要性、相关性三项归一化后等权相加，排在前面且放得进上下文的记忆进入 prompt（§1¶4、§4.1¶7）；模型不参与决定读什么，这在[模型自管理上下文](../concepts/model-managed-context.md#设计空间)的分类里属于 harness 一侧。
- **只存原始观察的 agent 不会概括；反思把观察提炼成关于自己和他人的推断，作为新记忆写回同一条流，还能在旧反思上再反思，形成反思树（§4.2¶1、§4.2¶4）**。去掉反思后，访谈可信度的 TrueSkill 均值从 29.89 降到 26.88（§6.5.1¶1），见[记忆流与反思](../concepts/memory-stream-reflection.md)。
- 记忆流只追加：反思和计划都作为新条目写入（§4.2¶3、§4.3¶2），论文没有改写或删除旧条目的机制。后来 A-MEM、Mem0 在写入时改写或删除旧条目，走的是另一条路线，见[写入时记忆整合](../concepts/memory-consolidation.md#设计空间)。
- 重要性在写入时由 LLM 打一次 1–10 分，此后不变（§4.1¶5）；本库判断：这让"什么值得记住"在记忆刚产生时就基本定下，之后的新信息改变不了旧记忆的分量，见[记忆流与反思](../concepts/memory-stream-reflection.md#开放问题)。
- 记忆越多越难用：作者观察到记忆增长后，检索相关信息和选择行动地点都更难（§7.2¶1），最常见的错误是没取回相关记忆和给记忆添油加醋（§1¶6），见[记忆流与反思](../concepts/memory-stream-reflection.md#开放问题)。
- 反思服务于行为可信度，评测的因变量就是可信度（§6.1¶1），存的是对人和事的推断，没有跨任务积累做事规则的设计；所以本库不把它归入[记忆笔记](../concepts/memory-notes.md)。

## 核心问题

LLM 能在单个时间点生成可信的人类行为，但要长时间保持连贯，agent 需要在不断增长的经历上检索、概括并据此规划（§1¶2）。当时的做法是一阶 prompting，只以当前环境为条件；经历多到放不进 context window，全部塞进去还会分散模型的注意力（§2.3¶2、§4.1¶1）。本质上这是长期记忆的取用问题：经历只增不减，每一步要决定把哪一小部分、以什么抽象层次放进 prompt。

## 核心洞察

所有经历都用自然语言记录，就能直接交给 LLM 检索和推理（§4¶2）。原始观察不足以支撑概括，需要定期把观察综合成更高层的反思；反思本身也是记忆，和观察一起参与检索（§4¶2、§4.2¶2）。

## 核心设计

1. **记忆流**：每个记忆对象是一段自然语言描述，带创建时间和最近一次访问时间；最基本的条目是 agent 直接感知到的观察（§4.1¶2）。这样所有模块读写的是同一种格式。
2. **三项打分检索**：近因按上次被检索以来的游戏小时数指数衰减，衰减因子 0.995（§4.1¶4）；重要性在写入时让 LLM 打 1–10 分（§4.1¶5）；相关性是记忆和查询嵌入的余弦相似度（§4.1¶6）。三项用 min-max 归一化后等权相加，取能放进上下文的前若干条（§4.1¶7）。
3. **反思**：最近事件的重要性之和超过 150 时触发，实际每天两三次（§4.2¶2）。先用最近 100 条记忆让 LLM 提出几个高层问题，用这些问题检索，再让 LLM 写出带证据编号的洞见，存回记忆流并保留指向被引记忆的指针（§4.2¶3）。反思可以引用反思，形成树（§4.2¶4、Fig. 7）。
4. **规划与反应**：先按 agent 的简介和前一天的摘要写出全天的粗计划，再递归分解成小时级和 5–15 分钟级的动作（§4.3¶3、§4.3¶4）；计划也存进记忆流参与检索（§4.3¶2）。每个时间步，agent 根据新观察决定继续原计划还是做出反应，反应后从当时起重新生成计划（§4.3.1）。
5. **环境的自然语言表示**：沙盒小镇 [Smallville](../glossary.md#smallville) 里的区域和物体组织成一棵包含关系树，每个 agent 只记得自己见过的子树，选地点时从根往下逐层让 LLM 选择（§5.1）。

实现用的是 gpt3.5-turbo 版的 ChatGPT（§4¶3）。

## 局限与疑点

### 作者承认的

- 检索会漏掉该取的记忆，或只取回片段，例如记得要在派对上谈选举，却不确定派对是否存在（§6.5.2¶2）。
- agent 会给记忆添油加醋，包括把语言模型的世界知识带进来，例如把邻居 Adam Smith 说成《国富论》的作者（§6.5.2¶3）。
- 记忆增长后，检索和选择行动地点都变难，部分 agent 的行为随时间变得不典型（§7.2¶1）。
- 指令微调让 agent 过于正式、过于合作，很少拒绝别人的提议（§7.2¶3）。
- 25 个 agent 模拟两天花了数千美元的 token，耗时数天（§8.2¶1）。
- 评测时间尺度短，人类基线只是众包工人，不代表人类表现的上限；对 prompt 攻击、"记忆攻击"和幻觉的鲁棒性未知（§8.2¶2）。

### 本库判断的

- 评测量的是可信度，由人对访谈回答排序（§6.1¶4），没有任务成功率一类的客观指标。这套记忆架构对"把事做成"有多大帮助，论文没有测。
- 消融条件不重新模拟，所有条件读的是完整架构两天积累下来的同一份记忆（§6.2¶1）。作者认为这让差异偏保守；本库判断：这样测的是回答问题时用不用反思和计划，没有测去掉某个模块后记忆本身会怎样长歪。
- 三项检索权重都设为 1、衰减因子 0.995（§4.1¶7、§4.1¶4），没有敏感性分析；作者也把调整这三个函数列为未来工作（§8.2¶1）。
- 记忆只追加，重要性写入后不变（§4.1¶5）。编造的内容一旦写成反思，会和真实观察一样被后续检索和反思引用（§4.2¶4），论文没有讨论怎样纠正写错的反思。
- "放不进 context window"这一前提（§4.1¶1）来自 2023 年的模型。窗口变长后这一条理由变弱，作者给的另一条理由是全部记忆会分散模型的注意力（§4.1¶1），它仍然成立与否需要新的实验。

## 与其他工作的关系

- 与 [MemGPT](./202310-memgpt.md)：MemGPT 在相关工作里把本文概括为给 LLM 加记忆并用 LLM 做规划（[MemGPT](./202310-memgpt.md) §4¶3）。两篇都把记忆放在上下文之外、按需取回；区别在谁决定取什么。本文由固定打分函数每步取回（§4.1¶7），MemGPT 让模型用函数调用自己检索和改写（[MemGPT](./202310-memgpt.md) §2.3¶1）。本库把这个差别放在[模型自管理上下文](../concepts/model-managed-context.md#设计空间)里比较。
- 与 [A-MEM](./202502-a-mem.md)、[Mem0](./202504-mem0.md)：三篇都由 LLM 在写入时加工记忆。本文只追加新条目（打重要性分、写反思），A-MEM 会改写近邻笔记的描述和标签（[A-MEM](./202502-a-mem.md) §3.3¶1），Mem0 会删除被新信息否定的事实（[Mem0](./202504-mem0.md) §2.1¶3），见[写入时记忆整合](../concepts/memory-consolidation.md#设计空间)。
- 与 Reflexion：两者都把经验提炼成文字再读回。Reflexion 反思的是任务失败的原因，供下一次尝试使用；本文反思的是对人和事的推断，供维持角色一致。Reflexion 的素材待录入。

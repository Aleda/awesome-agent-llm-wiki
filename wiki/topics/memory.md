## 这个方向在解决什么

LLM 的权重在部署后固定，两次调用之间不保留任何状态。agent 要在多次会话或很长的任务中保持连续，只能把信息存到模型之外，在需要时再取回放进上下文。难点有三处：哪些信息值得写入，写入后如何组织才能在需要时被检索到，旧信息过时或互相矛盾时如何更新。memory 方向关心存储和取回的机制；这些记录能否让 agent 在之后的任务上持续变好，归 continual learning 方向。

## 概念地图

### 记忆的结构

- 分层记忆：仿照操作系统的内存与外存，在上下文和外部存储之间换入换出（MemGPT 一类）。
- 记忆流与反思：按时间记录观察，定期提炼成更高层的总结（Generative Agents 一类）。
- 结构化记忆：把记忆条目组织成可链接、可修改的笔记或图（A-MEM、Mem0 一类）。
- [记忆笔记](../concepts/memory-notes.md)：把任务经验写成自然语言笔记并反复改写，目的是让后续任务做得更好；它同时属于 continual learning 方向。

### 读写策略

- 写入：由规则触发，还是由模型决定何时写、写什么。
- 检索：按相关性、时间和重要性打分取回。
- 更新与遗忘：合并重复条目、覆盖过时内容、处理冲突。

### 记忆的类型

- 情节记忆（发生过什么）、语义记忆（知道什么）、程序性记忆（会做什么）。

## 关键争论

- 模型管理还是外部系统管理：读写记忆的决策由模型自己做，还是由外部系统按规则做。这与 context 方向的同类争论是同一个问题。
- 检索够不够：向量检索能否应付需要跨多条记忆推理的情形，还是需要显式的结构（图、层级）。
- 怎么评测：现有评测多测"能否记起某个事实"，较少测"有了记忆后续任务是否做得更好"。后一类的一种设计是[连续任务流评测](../concepts/streaming-task-evaluation.md)。
- 产品层的连续性：NeoCognition 联创谷雨认为 personal agent 要做成一个持续存在的单一会话，按 session 开窗口的方式不适合做助手（[播客页](../podcasts/20261108-crossing-gu-yu.md) [00:36:42]），这把跨会话记忆从模型能力问题变成了产品形态问题。
